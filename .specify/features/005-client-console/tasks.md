# Tasks: Client Console (Satellite View & Orders)

**Input**: Design documents from `.specify/features/005-client-console/`
**Prerequisites**: `plan.md` (required), `spec.md` (required for user stories), `research.md`, `data-model.md`, `contracts/`, `quickstart.md`
**Branch**: `001-europa-core`
**Spec**: [spec.md](./spec.md) — 5 user stories (US1 = P1 Satellite Grid Within the Visibility Horizon, US2 = P1 Pipe Commands With Region Targeting, US3 = P2 Paratroop and Gun Targeting, US4 = P2 Reserves Control, US5 = P3 Modern Quality-of-Life Layer) and 11 functional requirements (FR-001..FR-011)

**Tests**: REQUIRED. Constitution Principle III mandates ≥80% coverage on game logic as a merge gate. Constitution Principle VI mandates WCAG 2.2 AA, so every user story has a dedicated a11y acceptance test. The plan's `quickstart.md` §3–§5 maps every spec FR to at least one test (Q-C01..Q-C03, Q-U01..Q-U10, Q-B01..Q-B08, Q-E01..Q-E15, Q-A01..Q-A08, Q-P01..Q-P04, plus the SC-002 determinism + subcell parity + self-host smoke tests). Tests are interleaved with implementation per the spec-kit template (failing tests first, then impl, then integration). The reducer is targeted at 100% coverage (pure function, free); `localPreflightOrder` is targeted at 100% (security-relevant per `plan.md` "Constitution Check" Principle III); the input mapping table is targeted at 100%; the package-wide floor is 80% (Vitest v8 thresholds).

**Organization**: Tasks are grouped by user story in spec-priority order. **Phase 3 (US1) = the MVP** — produces a renderable, a11y-compliant board that displays a fog-filtered `PlayerView` with the ARIA grid overlay. The MVP is testable standalone with a mock `PlayerView` (no live server needed per the prompt's MVP scope note). **Phase 4 (US2)** layers the region-based pipe input + keyboard equivalents (the original control set). **Phase 5 (US3)** layers subcell targeting for paratroops/guns. **Phase 6 (US4)** layers reserves control. **Phase 7 (US5)** layers modern QoL (zoom/pan, status, surrender, reconnect feedback, hotkeys, reduced-motion). The plan's "one file per pipeline phase" model and the prompt's directory layout are reconciled: the console lives in `packages/console/` (exported as `@europa/console`), mirroring the engine/fog/terrain/networking precedent (features 001–004). Drift between the four committed contract files under `.specify/features/005-client-console/contracts/` and the source-of-truth mirror under `packages/console/contracts/` is a bug caught by the conformance test (Polish phase).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: Which user story this task belongs to (`[US1]`–`[US5]`); REQUIRED for user story phase tasks only — Setup, Foundational, and Polish phases MUST NOT carry a story label
- Include exact file paths in descriptions — every task targets a specific file under `packages/console/`
- Spec user stories are the label, NOT the prompt's pipeline phases. The prompt's "Phase 1..8" headings correspond to the spec's user story phases 3..7 + Setup/Foundational/Polish (1/2/8). A task labeled `[US1]` lives in spec US1 (Satellite Grid), not prompt "Phase 1."

## Path Conventions

Per `plan.md` §"Project Structure" (monorepo root). The console lives at `packages/console/` as `@europa/console`, mirroring the engine/fog/terrain/networking precedent (features 001–004). The package's source tree uses one file per concern; the server-side equivalent of the console's `state/`, `net/`, `input/`, `render/`, `a11y/`, `qol/`, `ui/`, `internal/` subfolders follows the plan. The package's `index.ts` (Phase 8) is the public surface (`createConsole`, `CONSOLE_CONSTANTS`, `CONSOLE_API_VERSION`). The package's `tests/` is organized as `unit/` (per-module, Vitest 4.1 + happy-dom), `a11y/` (axe-core a11y unit tests, Vitest + `@axe-core/playwright` browser mode), `component/` (Vitest Browser Mode + `vitest-browser-react`, React components in real Chromium), `e2e/` (Playwright 1.6+ with axe-core integration), `integration/` (cross-module — conformance, determinism, perf, selfhost), and `fixtures/` (scripted PlayerView builders, mock client, mock WebSocket).

> **Path reconciliation (PM-mediated)**: the dispatch prompt specified `packages/client/` + `@europa/client` in its path conventions section. The committed `plan.md` uses `packages/console/` + `@europa/console`. **Decision in this tasks.md**: the plan's path is authoritative — matches the feature 001–004 precedent of `packages/{engine,fog,terrain,networking,console}/` and the package-name=directory-name convention. This tasks.md uses `packages/console/` throughout. See **PM Handoff §1** for the open question.
