# Tasks: Match Lifecycle & Matchmaking

**Input**: Design documents from `.specify/features/006-match-lifecycle-matchmaking/`
**Prerequisites**: `plan.md` (required), `spec.md` (required for user stories), `research.md`, `data-model.md`, `contracts/`, `quickstart.md`
**Branch**: `001-europa-core`
**Spec**: [spec.md](./spec.md) — 5 user stories (US1 = P1 Quick Match Creation and Auto-Start, US2 = P2 Lobby Browser for Public Matches, US3 = P2 Private Matches via Shareable Link, US4 = P2 Game Over and Rematch, US5 = P3 Disconnect Forfeit Policy) and 12 functional requirements (FR-001..FR-012)

**Tests**: REQUIRED. Constitution Principle III mandates ≥80% coverage on game logic as a merge gate (Vitest v8 coverage threshold enforced in `vitest.config.ts`). Each module gets a parallel unit test file under `packages/matchmaking/tests/unit/`. Acceptance scenarios live as runnable quickstart files under `packages/matchmaking/tests/quickstart/` (Q-M01..Q-M08 from `quickstart.md`), with `tests/conformance.test.ts` asserting the matchmaker's call-site shapes match feature 004's `Server` API, and `tests/soak.test.ts` running 50 sequential create/play/finish cycles (SC-005).

**Organization**: Tasks are grouped by user story in spec-priority order. **Phase 3 (US1) = the MVP** — produces a working matchmaker that creates a public 2-player match, seats the creator, accepts a joiner, auto-starts the engine via `server.registerMatch` + `server.attachPlayer`, and exposes a synchronous `listPublicMatches()` projection. The MVP is testable standalone with the `FakeServer` fixture (no live networking/engine needed). **Phase 4 (US2)** layers the public lobby filtering. **Phase 5 (US3)** layers private visibility + shareable join URLs + the single `match_not_found` code path. **Phase 6 (US4)** layers rematch coordination. **Phase 7 (US5)** layers the disconnect-forfeit policy. **Phase 8** is Polish: conformance test, soak test, README, CI workflow, governance flips.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: Which user story this task belongs to (`[US1]`–`[US5]`); REQUIRED for user story phase tasks only — Setup, Foundational, and Polish phases MUST NOT carry a story label
- Include exact file paths in descriptions — every task targets a specific file under `packages/matchmaking/`
- Spec user stories are the label, NOT the pipeline phases. A task labeled `[US1]` lives in spec US1 (Quick Match Creation), not "Phase 1."

## Path Conventions

Per `plan.md` §"Project Structure" (monorepo root). The matchmaker lives at `packages/matchmaking/` as `@europa/matchmaking`, mirroring the engine/fog/terrain/networking/console precedent (features 001–005). ## Phase 3: User Story 1 - Quick Match Creation and Auto-Start (Priority: P1) 🎯 MVP

**Goal**: Deliver the matchmaker's create + join + auto-start core loop. After this phase, two scripted clients can call `createMatch` + `joinMatch` against the matchmaker (driving a `FakeServer` fixture), the second seat-fill triggers an atomic `filling → running` transition that calls `server.registerMatch` + `server.attachPlayer` × N, and the lobby projection reflects the transition within one mutation. The MVP is the `lobby.ts` + `matchLifecycle.ts` + `matchmaker.ts` trio.

**Independent Test**: Per `quickstart.md` Q-M01 + Q-M07: drive the matchmaker with a `FakeServer` (T065 lands this fixture in Phase 8); assert (a) Alice's `createMatch` returns seat 0 with a `MatchId` + `joinPath`; (b) Bob's `joinMatch` returns seat 1 with the same `MatchId`; (c) the transition `filling → running` triggered exactly one `server.registerMatch` call and exactly two `server.attachPlayer` calls; (d) `listPublicMatches()` returns the match in step 1 and excludes it after step 3; (e) five concurrent joiners for the last seat: exactly one succeeds, four return `match_full` (Q-M07 atomicity).

**⚠️ MVP scope clarification**: The MVP in this phase handles the create/join/auto-start path only. Rematch (Phase 6), private visibility (Phase 5 — except for the type field which Phase 3 already wires), forfeit (Phase 7), and the spec's rematch window/forfeit GC (Phase 8) are NOT exercised by the US1 acceptance test. The MVP demonstrable surface is "two scripted players can create a public 2-player match, the second seat-fill auto-starts the engine session, and the lobby reflects the transition."
