# Data Model: Match Lifecycle & Matchmaking (Feature 006)

**Branch**: `001-europa-core`
**Date**: 2026-08-21
**Spec**: `.specify/features/006-match-lifecycle-matchmaking/spec.md` (v1.1)

> All entities live in `packages/matchmaking/src/` and are re-exported via `@europa/matchmaking` to the server binary. Types are `Readonly<...>` everywhere outside the matchmaker's own internal mutation during lifecycle transitions; the public `Matchmaker` interface returns immutable snapshots.
>
> Branded primitives (`MatchId`, `PlayerSessionId`) prevent type confusion between match IDs, session tokens, and connection IDs (the latter two are owned by feature 004; we re-use networking's brands).
>
> Field types are described here in TypeScript-flavored notation. Public surfaces live in `contracts/match-types.ts`; server-internal records (`MatchRecord`, `SeatRecord`, `PlayerSession`) are declared in `src/internal/*.ts` and exported only for testability (the `@internal` JSDoc tag signals this).

---

## 1. `MatchId` (re-used from networking)

### Definition

```ts
// Already declared in @europa/networking's network-types.ts line 55.
// Re-exported here for convenience so consumers of @europa/matchmaking
// don't need a second import.
export type { MatchId } from '@europa/networking';
```

### Constraints

- UUID v4 string (36 chars, hyphenated) — see `research.md` §1.
- Branded `string & { readonly __brand: 'MatchId' }`.
- Server-issued; opaque to clients; clients use the value verbatim to address a match.

## 2. `PlayerSessionId` (new — matchmaking-owned ephemeral identity)

### Fields

| Field         | Type                                  | Constraints                       | Notes |
|---------------|---------------------------------------|-----------------------------------|-------|
| (brand only)  | `string & { readonly __brand: 'PlayerSessionId' }` | UUID v4, 36 chars           | Opaque to clients; displayed as "Player #abc123" in UI |

### Relationships

- 1 `PlayerSession` (Section 11) per `PlayerSessionId`.
- A `PlayerSession` may hold at most one `MatchId` (the match they're currently in) and one `SeatIndex` (their position in that match).
- Disjoint from `MatchId`, `SessionToken`, `ConnectionId` — separate brands, separate namespaces.

### Validation rules

- Format: UUID v4 with hyphens.
- Generated by the matchmaker on first `createMatch` / `joinMatch` from a given client.
- Not persisted across server restart (in-memory only).

## 3. `MatchVisibility` — `'public' | 'private'`

### Definition

```ts
export type MatchVisibility = 'public' | 'private';
```

### Semantics

- **`public`**: match appears in `listPublicMatches()` output. Joinable by anyone who knows the `MatchId` (the lobby is the discovery mechanism; the URL is just one delivery channel).
- **`private`**: match does NOT appear in `listPublicMatches()`. Joinable only by someone who knows the `MatchId` (typically delivered via shareable URL). Matches the spec v1.1 Q1 + Q2 clarifications.

### Validation rules

- Visibility is fixed at match creation. No mutation API. Spec edge case "creator wanted privacy after all" → recreate the match.
- Both visibility types have the same internal lifecycle; the only difference is lobby listing.

## 4. `MatchStatus` — the lifecycle state machine

### Definition

```ts
export type MatchStatus = 'filling' | 'running' | 'finished' | 'collected';
```

### State diagram

```
                 createMatch (creator seated)
                 │
                 ▼
           ┌───────────┐    all seats filled +
           │  filling  │    engine session constructed
           └─────┬─────┘    (synchronous atomic transition)
                 │  ◄────────────┐
                 │               │ creator/other leaves before start
                 │               │ OR emptyMatchTtlMs expires
                 │               │
                 ▼               │
           ┌───────────┐         │
           │ collected │ ◄───────┘
           └───────────┘
                 ▲
                 │  results delivered + rematch window
                 │  (60 s default) OR all declined OR
                 │  no rematch offered
                 │
           ┌───────────┐
           │ finished  │
           └─────┬─────┘
                 ▲
                 │  engine reports terminal
                 │  (running → finished)
                 │
           ┌───────────┐
           │  running  │
           └───────────┘
```

### Transitions

| From       | To         | Trigger                                                  | Side effects |
|------------|------------|----------------------------------------------------------|--------------|
| (none)     | `filling`  | `createMatch` succeeds                                   | Add to lobby (if public); seat player 0 |
| `filling`  | `running`  | `joinMatch` fills the last seat                          | Generate board; construct engine session; `server.registerMatch`; `server.attachPlayer` × N |
| `filling`  | `collected`| `leaveMatch` by creator (no other seats) OR `emptyMatchTtlMs` elapses | Remove from lobby; release seats; no engine session was created |
| `running`  | `finished` | Engine reports `MatchResult` (via `onMatchTerminal`)     | Record `MatchResultsRecord`; open rematch window; broadcast results |
| `finished` | `collected`| `resultsTtlMs` elapses OR all rematch votes resolved (accept → new match; decline → collected) | Release seats; close engine session; `server.unregisterMatch` |
| `running`  | `collected`| ALL players forfeited (US5 AC-2)                        | Record `MatchResultsRecord` with `kind: 'cancelled'`; close engine session; `server.unregisterMatch` |

### Validation rules

- `MatchStatus` is server-internal; clients receive `MatchStatusChanged` events over the network transport (via feature 004 protocol messages — out of scope for the matchmaker contract).
- Transitions are atomic. A `filling → running` transition cannot be interrupted by a concurrent `leaveMatch` (the seat-fill check + transition happens inside one synchronous critical section; see §5).

## 5. `MatchRecord` (server-internal; @internal)

### Fields

| Field             | Type                                | Constraints                                  | Notes |
|-------------------|-------------------------------------|----------------------------------------------|-------|
| `matchId`         | `MatchId`                           | unique; UUID v4                              | |
| `visibility`      | `MatchVisibility`                   | `'public'` or `'private'`                    | Fixed at creation |
| `status`          | `MatchStatus`                       | initial: `'filling'`                         | §4 |
| `settings`        | `MatchSettings`                     | non-null                                     | §6 |
| `engineConfig`    | `MatchConfig` (from engine)         | frozen when status transitions to `running`  | Feature 001's type |
| `seats`           | `Map<SeatIndex, SeatRecord>`        | size = `settings.playerCount` once `running` | §7 |
| `createdAtMs`     | `number`                            | epoch ms                                     | Set at createMatch |
| `startedAtMs`     | `number \| null`                    | epoch ms; set on `filling → running`         | |
| `finishedAtMs`    | `number \| null`                    | epoch ms; set on `running → finished`        | |
| `results`         | `MatchResultsRecord \| null`        | set on `running → finished`                  | §10 |
| `rematch`         | `RematchOffer \| null`              | non-null iff a rematch window is open        | §9 |
| `engineSession`   | `EngineSession \| null`             | set when status transitions to `running`     | Feature 001's type |
| `lastActivityAtMs`| `number`                            | epoch ms; updated on every state-changing op | Used for empty-match TTL |
| `joinPath`        | `string`                            | `/join/<matchId>`; immutable                 | §8 |

### Validation rules

- `engineSession` is `null` iff `status === 'filling'` or `'collected'`.
- `results` is non-null iff `status === 'finished'` or `'collected'` after having been `finished`.
- `seats.size <= settings.playerCount` always.
- `lastActivityAtMs` is updated on every `createMatch` / `joinMatch` / `leaveMatch` / `requestRematch` / `acceptRematch` / `declineRematch` call.

### Relationships

- 1 `MatchRecord` → N `SeatRecord` (composition; one per occupied seat).
- 1 `MatchRecord` → 0..1 `EngineSession` (composition; one per running match).
- 1 `MatchRecord` → 0..1 `RematchOffer` (composition; at most one active at a time).
- 1 `MatchRecord` → 0..1 `MatchResultsRecord` (composition; at most one ever).

## 6. `MatchSettings` (player-facing tunables; passed to `createMatch`)

### Fields

| Field             | Type                          | Constraints                                  | Notes |
|-------------------|-------------------------------|----------------------------------------------|-------|
| `playerCount`     | `2 \| 3 \| 4`                 | v1 ships 2 (AGENTS.md); contract supports 2–4 | Engine FR-019 |
| `boardSize`       | `number` (integer)            | `>= 8`, `<= 128`; default `32`               | Terrain constraint |
| `terrainSettings` | `GenerationSettings`          | from `@europa/terrain`; default = `DEFAULT_GENERATION_SETTINGS` | FR-008 |
| `tickIntervalMs`  | `number` (integer)            | `> 0`; default `250`                         | Engine default; matches networking |

### Validation rules

- `boardSize` is clamped to `[8, 128]`; out-of-range values are rejected with `invalid_request`.
- `playerCount = 2` for v1 end-to-end; `3` and `4` are accepted by the API but lightly tested (per AGENTS.md binding decision + spec assumption).
- `terrainSettings` may be omitted; defaults are filled from `DEFAULT_GENERATION_SETTINGS`.

### Relationships

- `MatchSettings` is the input to `createMatch` and is **immutable** for the match's lifetime.
- `MatchSettings` is converted to `MatchConfig` (engine) + `TerrainGenerationRequest` (terrain) + `ServerConfig.tickRateMs` (networking) at match start.

## 7. `SeatRecord` (server-internal; @internal) + `SeatIndex`

### `SeatIndex`

```ts
export type SeatIndex = number; // 0..(playerCount - 1); integer
```

### `SeatRecord`

| Field             | Type                                  | Constraints                       | Notes |
|-------------------|---------------------------------------|-----------------------------------|-------|
| `seatIndex`       | `SeatIndex`                           | `0 <= seatIndex < playerCount`    | Position in seat order |
| `playerSessionId` | `PlayerSessionId`                     | non-null                          | Ephemeral identity (FR-001) |
| `displayName`     | `string`                              | `1 <= length <= 32`               | Cosmetic; FR-001 |
| `sessionToken`    | `SessionToken`                        | UUID v4                           | Networking-bound (FR-003 of feature 004 boundary) |
| `playerId`        | `PlayerId \| null`                    | non-null iff `status === 'running'` | Engine PlayerId (1..playerCount) |
| `connectedAtMs`   | `number`                              | epoch ms                          | Set at attachPlayer |
| `forfeitedAtMs`   | `number \| null`                      | epoch ms; set on `onSeatExpired`  | Terminal for the seat |

### Validation rules

- `playerId` is assigned when the match transitions to `running` (atomic with `server.attachPlayer`).
- Disconnect/reconnect state is NOT recorded on `SeatRecord`: networking owns the grace window on its own seat records and reports only the expiry (`onSeatExpired`) across the bridge; `onSeatDisconnected`/`onSeatReconnected` are deliberate no-ops in the matchmaker.
- `forfeitedAtMs` is set by the matchmaker on `onSeatExpired` (see `forfeit.ts`); the seat is surrendered to the engine via `OrderSurrender`.

### Relationships

- N `SeatRecord` per `MatchRecord` (one per occupied seat).
- 1 `SeatRecord` → 1 `PlayerSession` (lookup via `playerSessionId`).
- 1 `SeatRecord` → 1 `SessionToken` (lookups during reconnect).

## 8. `JoinPath` + `JoinUrlResult` (returned to clients)

### `JoinPath`

```ts
export type JoinPath = string; // always of the form `/join/<matchId>`
```

### `JoinUrlResult`

| Field         | Type        | Constraints                | Notes |
|---------------|-------------|----------------------------|-------|
| `matchId`     | `MatchId`   | UUID v4                    | Spec FR-003 |
| `joinPath`    | `JoinPath`  | `/join/<matchId>`          | Relative path; host composes full URL |
| `joinUrl`     | `string \| null` | non-null iff `MatchmakerConfig.publicBaseUrl` is set | Full URL (FR-003 + Q3 clarification) |

### Rationale

- The matchmaker does not know its public base URL (self-hostable deployments may have any URL). It always returns `joinPath`; the host server binary composes the full URL using `config.publicBaseUrl` if set, or by passing `joinPath` to a templating layer.
- If the matchmaker is constructed with `publicBaseUrl: 'https://europa.example.com'`, then `joinUrl` is also returned, already prefixed. Clients can share `joinUrl` directly.

## 9. `RematchOffer` (server-internal; @internal)

### Fields

| Field             | Type                                | Constraints                                  | Notes |
|-------------------|-------------------------------------|----------------------------------------------|-------|
| `offerId`         | `MatchId` (new)                     | UUID v4; distinct from the original matchId | New match identity |
| `windowExpiresAtMs` | `number`                          | epoch ms; set at `finished`                  | `finishedAtMs + rematchWindowMs` |
| `acceptedBy`      | `Set<PlayerSessionId>`              | empty initially                              | Players who have voted accept |
| `declinedBy`      | `Set<PlayerSessionId>`              | empty initially                              | Players who have voted decline |
| `allOriginalPlayerIds` | `ReadonlyArray<PlayerSessionId>` | snapshot of the original match's seated players | Used to compare against `acceptedBy` |
| `newMatchRecord`  | `MatchRecord \| null`               | set when `acceptedBy.size === allOriginalPlayerIds.size` | The new match, already in `'filling'` |

### Validation rules

- All sets operate over `PlayerSessionId`, not `PlayerId`, because a rematch participant may have been forfeited and lost their `SessionToken` (they're effectively absent from the vote).
- `declinedBy.size > 0` immediately transitions the original match to `collected` (early termination; spec edge case).
- `windowExpiresAtMs` is checked on every `listPublicMatches()` call and on the next mutation; if expired without resolution, the match transitions to `collected`.

### State machine

```
                    results delivered
                    (finished)
                    │
                    ▼
              ┌────────────┐
              │  pending   │  ───── windowExpiresAtMs ─────► collected
              └─────┬──────┘
                    │ all original participants in `acceptedBy`
                    ▼
              ┌────────────┐
              │  resolved  │  (new match created in 'filling'; original transitions to 'collected' after results delivery)
              └────────────┘
```

### Relationships

- 1 `RematchOffer` per `finished` `MatchRecord` (zero or one; never more than one at a time).

## 10. `MatchResultsRecord` (re-used from `engine-to-matchmaking.ts`) + matchmaker extension

The shape is defined in feature 001's `engine-to-matchmaking.ts` line 74. The matchmaker re-uses the engine's `MatchResultsRecord` verbatim and stores matchmaker-specific metadata on the `MatchRecord` (NOT on the `MatchResultsRecord` itself, to keep the engine ↔ matchmaking boundary clean).

### Fields (from the engine)

| Field               | Type                                                                       | Source                          | Notes |
|---------------------|----------------------------------------------------------------------------|---------------------------------|-------|
| `matchId`           | `MatchId`                                                                  | §1                              | |
| `tick`              | `number`                                                                   | engine                          | tick when terminal |
| `effectiveSeed`     | `number`                                                                   | engine                          | FR-008 |
| `result`            | `MatchResult \| { kind: 'cancelled'; reason: string }`                     | engine / matchmaker             | `cancelled` is matchmaker-only (all-disconnected case) |
| `finalBoardHash`    | `string`                                                                   | engine                          | |
| `finalPlayers`      | `ReadonlyArray<{ id: PlayerId; displayName: string; status: ...; finalTroops: number; finalCities: number }>` | engine | |

### Fields (matchmaker-added, stored on `MatchRecord`, NOT on `MatchResultsRecord`)

| Field               | Type                                                                       | Source                          | Notes |
|---------------------|----------------------------------------------------------------------------|---------------------------------|-------|
| `deliveredAtMs`     | `number`                                                                   | matchmaker                      | Epoch ms when results were sent to clients |
| `durationMs`        | `number`                                                                   | matchmaker                      | `finishedAtMs - startedAtMs` |

### Validation rules

- `result.kind === 'cancelled'` is reserved for the all-disconnected case (US5 AC-2). All other results come from the engine.
- The matchmaker-specific fields are stored on the `MatchRecord` (alongside `startedAtMs`, `finishedAtMs`, etc.) to keep the engine's `MatchResultsRecord` boundary pristine.

### Fields

| Field             | Type                                  | Constraints                       | Notes |
|-------------------|---------------------------------------|-----------------------------------|-------|
| `playerSessionId` | `PlayerSessionId`                     | UUID v4                           | §2 |

- 1 `PlayerSession` → 0..1 `SeatRecord` (via `currentMatchId` + `currentSeatIndex`).

## 12. `LobbyEntry` (public projection of a `MatchRecord`)

### Fields

| Field               | Type                | Constraints                       | Notes |
|---------------------|---------------------|-----------------------------------|-------|
| `matchId`           | `MatchId`           | UUID v4                           | |
| `hostDisplayName`   | `string`            | non-empty                         | Creator's display name |
| `playerCount`       | `number`            | `2..4`                            | |
| `seatsFilled`       | `number`            | `1..playerCount`                  | |
| `boardSize`         | `number`            | `8..128`                          | |
| `visibility`        | `MatchVisibility`   | always `'public'` for lobby entries | Spec FR-005 |
| `createdAtMs`       | `number`            | epoch ms                          | |
| `ageSeconds`        | `number`            | `(now - createdAtMs) / 1000`      | Computed at projection time |

### Validation rules

- `LobbyEntry` is only produced for matches with `status === 'filling'` AND `visibility === 'public'`. `running`, `finished`, `collected` matches are excluded.
- The projection is rebuilt on every `listPublicMatches()` call (read-mostly; O(N) for N joinable matches).

### Why this shape (vs. exposing the full `MatchRecord`)

- `LobbyEntry` excludes `engineSession`, `seats[*].sessionToken`, `results`, and any other server-internal state. Clients see only what the spec mandates (FR-005: "id, display info, seat occupancy, settings").
- `LobbyEntry` excludes private matches entirely.

### `MatchmakerError`

| Field     | Type                  | Constraints                       | Notes |
|-----------|-----------------------|-----------------------------------|-------|
| `code`    | `MatchmakerErrorCode` | closed union                      | |

| `detail`  | `Readonly<Record<string, string \| number \| boolean>>` (optional) | machine-readable | For tests and logs |

## 19. Validation rules summary (matchmaker-enforced)

| Rule | Source |
|------|--------|
| `displayName` length ∈ `[1, maxDisplayNameLength]` | FR-001 |
| `visibility` is one of `'public'` / `'private'` | FR-002 |
| `MatchId` is server-issued (clients cannot choose) | FR-003 |
| Creator is auto-seated in seat 0 at `createMatch` time | FR-004 |
| Lobby listing contains only `filling` + `public` matches | FR-005 |
| Unknown `MatchId` → `match_not_found` (no existence leak) | FR-006 |
| Seat assignment is atomic on `filling → running` | spec edge case "race to fill" |
| Engine `OrderSurrender` is injected on `onSeatExpired` | FR-010 |
| Empty unstarted matches GC'd after `emptyMatchTtlMs` | FR-011 |
| All lifecycle transitions emit `MatchStatusChanged` | FR-012 |
| Rematch requires all original participants to accept within `rematchWindowMs` | FR-009 |
